# Lazada Open Platform API Guide

Use this skill to answer exact Lazada Open Platform API structure questions and
avoid guessing fields.

## Coverage

- Platform: Lazada Open Platform (`isvconsole.lazada.com` / `open.lazada.com`).
- 33 category folders with content under `references/api/` (System API, Seller API,
  Product API, Cross Boarder Product API, Media Center API, Flexicombo API,
  Order API, Return and Refund API, Fulfillment API, Logistics API, Finance API,
  Membership API, FBL API, Instant Messaging API, Lazada Logistics API, E-Tickets
  API, LazPay API, Sponsored Solutions API, Choice Customized API, LazLike API,
  Logistics Station API, etc.), 372 API docs total.
- Each doc has YAML frontmatter (`title`, `category`, `api_name`, `method`, `path`) plus
  structured sections: `## API Description`, `## Common Parameters`,
  `## Request Parameters`, `## Response Parameters`, `## Endpoints (by region)`,
  `## Error Codes`, `## Examples`.
- Request/Response Parameters are flattened nested trees (field paths use `.` to show
  parent→child, e.g. `data.address_shipping.city`), with type and required flags.
- Common Parameters are the shared auth/sign fields (app_key, timestamp, access_token,
  sign_method, sign).
- Endpoints by region lists the country-specific REST base URL per nation
  (e.g. `https://api.lazada.co.id/rest` for Indonesia).

## Workflow

1. Read the request and identify the business capability and any explicit method/path.
2. Map the capability to a category (e.g. product create → `Product API`,
   order list → `Order API`, member link → `Membership API`).
3. Inspect `references/api/<Category>/<operationName>.md` for the matched API.
4. Search `references/api/` by operation title, endpoint path, or keyword when the
   category is unclear.
5. Read the exact method (`GET`/`POST`/`GET/POST` in frontmatter/body), the HTTP path,
   the Common Parameters (auth/sign), the Request/Response parameter tables, the region
   endpoints, and the error codes.
6. Note that some API titles are duplicated across different paths; the docs use a
   numeric suffix (e.g. `GetLinkMemberList.md` vs `GetLinkMemberList_2.md`) to tell them
   apart — verify the `path` in frontmatter before answering.
7. If a schema, deprecation, or newer version is not present in the local reference,
   check the official Lazada Open Platform docs
   (`https://open.lazada.com/apps/doc/api?path=<path>`) and state the gap/source.
8. Do not invent fields, enum values, required flags, or response shapes that are absent
   from the selected API's official schema.

## References

- `references/api/<Category>/<operationName>.md` — one clean Markdown doc per Lazada API.
- Category folders map to Lazada categories (e.g. `Product API`, `Order API`,
  `Membership API`, `FBL API`).

## Update & Provenance

- Local reference is a **static snapshot**. It is regenerated by the toolchain in the
  `updskills` repo (`tools/bulk_render_lazada.py`) which pulls the official category
  manifest from
  `https://isvconsole.lazada.com/handler/share/apidoc/getApiCategoryMixed.json` and
  per-API details from
  `https://isvconsole.lazada.com/handler/share/apidoc/getApi.json?path=<path>`
  (pure JSON — no SPA rendering). To get fresher APIs, re-run that tool rather than
  hand-editing.
- For agent use, prefer the official live docs for anything that may have changed since
  this snapshot (deprecations, new scopes, policy).
